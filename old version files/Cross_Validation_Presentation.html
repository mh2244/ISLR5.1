Hello, today we will be talking about chapter 5.1, which is about cross-validation methods. We will be covering the validation set approach, leave-one-out cross-validation, k-fold cross-validation, bias-variance trade-off for k-fold CV, and cross-validation on classification problems.

The Problem

  • From previous chapters, we learned how to fit linear and logistic regression models
  • We want to know how well each candidate model will generalize to new data
  • For linear regression models, \(MSE_{Training} = \frac{1}{n} \sum_{i=1}^{n} (y_i-\hat{y}_i)\) is a poor estimate of \(MSE_{Test}\)
  • If no test set is available, we can hold out a subset of our training data as a validation set to obtain \(\hat{MSE}_{Test}\)

From previous sections, we learned how to fit linear and logistic regression models to our data. From that process, we will end up with multiple candidate models. We might want to know how well each model generalizes to new data, in the form of a test set. For linear regression models, we would quantify that error measure using the test MSE. However, what if a test set isn’t available? Using the training MSE that we obtain while fitting the model is often a poor and overly-optimistic estimate of the test MSE since the model is optimized to the training data. If no test set is available, we can hold out a subset of our training data, our validation or hold-out set, to obtain the estimated test MSE, and that’s the essence of the cross-validation methods we’re talking about today.

  • Auto dataset in ISLR2 library: gas mileage, horsepower, and 7 other variables for 392 vehicles.
  • Response variable: miles per gallon (mpg)

  1. \(y = \beta_0 + \beta_1 x + \epsilon\)
  2. \(y = \beta_0 + \beta_1 x+ \beta_2 x^2 + \epsilon\)

\(\vdots\)

  1. \(y = \beta_0 + \beta_1 x + \beta_2 x^2 + ... + \beta_{10} x^{10} + \epsilon\)
  • \(\epsilon \sim N(0, \sigma^2)\)

Therefore, in addition to the simple linear regression model, we are also considering models with polynomial terms horsepower. In the textbook, they’ve considered models with polynomial terms up to and including degree 10.

Validation Set Approach

  • Divide the available dataset once into two parts:
    • Training set
    • Validation set or Hold-out set
  • The percentage of data to allocate for training versus validation sets can vary

In the validation set approach, we randomly split the available data once into 2 sets: our training data, which we use to fit the model, and our validation or hold-out dataset. In the textbook example, they’ve done a 50/50 split. The percentage of how much to allocate to the training vs. test dataset can vary. For example, in undergraduate statistics courses, you might have been taught to do a 70/30 or 80/20 split, where a majority of data is used for training and we hold out a smaller percentage as the validation set. A schematic is presented here, where blue indicates the training dataset and orange the testing dataset. They’ve listed observations 7, 22, and 13 in the training set, and 91 in the validation set. We use our fitted model to predict the observations in the test dataset, then compare the error, or validation MSE to assess the accuracy of the model. However, there are some major disadvantages to using this approach.

Disadvantages of the Validation Set Approach

  • High Variance: \(\hat{MSE}_{Test}\) can vary depending on which data points end up in the training versus validation sets.
  • Bias: The full dataset is not used to fit the model, so \(\hat{MSE}_{Test}\) may be overestimated.

The first major drawback is that the MSE can vary a lot depending on which observations end up in your training versus your validation sets. The left plot shows the MSE we might observe by only running the validation method once across all our model candidates, which form a MSE curve. However, if we were to run the validation method many times over and plot an MSE curve for each iteration of the method, we might observe something on the right. Moreover, because we split the dataset, our training set becomes smaller, so the model error would also be inflated. The only real takeaway we might get from this plot is that a linear model with a quadratic term substantially decreases the estimated test MSE, but you wouldn’t know what the expected or average MSE curve would look like.

Leave-One-Out Cross-Validation

  • Divide the dataset into 2 parts:
    • Validation set has 1 observation: \((x_1, y_1)\).
    • Training set has \(n-1\) observations: \({(x_2, y_2), (x_3, y_3),...,(x_n, y_n)}\).
  • Calculate \(\hat{MSE}_{Test}^{(1)} = (y_1 - \hat{y}_1)^2\). Repeat \(n\) times such that each observation gets to be in the validation set and obtain \(n\) MSEs.
  • CV Estimate: \(CV_{(n)} = \frac{1}{n} \sum_{i=1}^{n} \hat{MSE}_{Test}^{(i)}\)

In each iteration, a different data point is chosen to be in the validation set, shown in orange. The training set is shown in blue.

This is where leave-one-out cross-validation comes in. Basically, the validation set will consist of 1 observation and the model is trained on the rest of the n-1 data points. We calculate the MSE for that data point, then we repeat this process such that every data point gets a turn at being in the validation set. An illustration of what this process looks like is in the figure below. In the end, we’ll average all n MSEs, which is called the CV estimate in the textbook, and we can compare CV estimates across different candidate models.

Advantages of LOOCV Over the Validation Set Method

  • Less bias since \(n-1\) observations are used to fit the model.
  • Method is completely deterministic (i.e. no variance in CV estimate curves across different runs).

The biggest advantages to this approach compared to the validation set are that it reduces bias over overestimating the test MSE and it is less likely to overestimate the MSE since we’re using n-1 observations or most of the dataset to fit the model. This can be seen in the figure below. The left graph shows what we might see if we were to just apply LOOCV. The right graph does multiple simulations of LOOCV, and unlike the validation method, we can see that even across different runs, the MSE does vary, but it’s a lot less compared to the validation method.

Disadvantages of LOOCV

  • LOOCV can be computationally expensive. The model must be fit \(n\) times.
  • \(CV_{(n)} = \frac{1}{n} \sum_{i=1}^{n} \left( \frac{y_i - \hat{y_i}}{1-h_i} \right)\)
    • \(\hat{y}_i\): ith fitted value from original least squares fit.
    • \(\hat{h}_i = \frac{1}{n} + \frac{(x_i - \bar{x})}{\sum_{i' = 1}^{n} (x_{i'} - \bar{x})}\): Leverage term between \(\frac{1}{n}\) and 1.

While LOOCV can be computationally expensive, we can reduce that cost by using the formula below. In the previous CV estimate equation we showed you, y_i hat was the prediction from the model fitted on n-1 data points, whereas here it’s fitted on all n data point (least squares fit, which includes all n datapoints). Since this means including the observation used in the validation set, the estimated MSE we get might be underestimated, so we offset that by weighting the error term by the leverage, which is described in Ch 2 but basically tells us how much influence each data point has. Doing this will give us the same CV estimates from the previous equation, but is computationally faster.

K-fold Cross Validation

  • Randomly divide set of observations into “folds” of approximately equal size.
    • First fold becomes the validation set.
    • The remaining \(k-1\) folds become the training set.
  • Repeat process \(k\) times to obtain \(k\) \(\hat{MSE}_{Test}\)s.
  • K-fold CV Estimate: \(CV_{(k)} = \frac{1}{k} \sum_{i=1}^{k} \hat{MSE}_{Test}^{(i)}\).

Another alternative to LOOCV is k-fold cross-validation. In this approach, we’re dividing the set of observations into \(k\) groups of \(folds\), of approximately equal size. The first fold is treated as validation set, and the method is fit on the remaining \(k-1\) folds or sets. The estimated test MSE is calculated based on the validation set, or the held-out fold. We repeat this process \(k\) times, as seen in the figure below. After that, we obtain the k-fold CV estimate by averaging those MSEs together. We can also see how the LOOCV is basically a special case of k-fold CV but using \(n\) folds. K-fold CV is computationally less expensive in this regard. The textbook recommends 5 or 10 folds due to the bias-variance trade-off, which Shrey will be going over later.

Using CV Estimates to Choose a Candidate Model

  • We can use CV estimates to help us decide on a candidate model by looking at the minimum of the curve.

Minimum MSEs are indicated with a cross. True MSE curve is blue. Dashed black and orange lines represent LOOCV and 10-fold CV estimates, respectively.

Of course, while validation MSE and CV estimates are better than training error as an estimate of the test error/test MSE, can we rely on them to choose between model candidates for the one whose flexibility best suits the data? Mostly, yes. To give some context, this figure isn’t based on the Auto dataset, but on 3 different data-generating functions not shown here, but they’re from chapter 2. For each dataset generated from that function, they’ve fit a model to it and applied LOOCV (black dashed) and 10-fold CV (orange) across different smoothing spline models with varying degrees of flexibility, and also calculated the true test MSE curve, shown in blue. In the first plot, CV estimates underestimate the true test MSE, second plot, it overestimates at higher degrees of flexibility, and the third plot it follows the true MSE curve fairly well. However, when selecting among different candidate models, we care more about the minimum of the MSE curves and whether they align with the true MSE–minimums are indicated by the crosses–from these simulations, we can see that while they don’t align exactly, it can give us a good enough approximation of which model to choose.
